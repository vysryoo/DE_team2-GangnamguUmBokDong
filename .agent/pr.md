# Pull Request 작성 규칙

`AGENTS.md`의 공통 원칙이 이 문서보다 우선한다. type 목록은 `AGENTS.md` 부록을 따른다.

리뷰어가 코드를 열어보기 전에 맥락을 파악할 수 있도록 돕는 것이 목적이다.

---

## 1. 제목 규칙

커밋 제목과 동일한 형식을 쓴다.

```
<type>: <한국어 요약>
```

- 요약은 70자 이내로 작성하고, 끝에 마침표를 붙이지 않는다.
- "무엇을 했는지"를 쓴다. "무엇을 하려 했는지"나 "어떤 파일을 고쳤는지"가 아니다.

```
좋음: feat: 리프레시 토큰 기반 자동 로그인 지원
좋음: fix: 주문 취소 시 재고가 복구되지 않는 문제 수정
나쁨: feat: UserService.java 수정          (파일명 나열)
나쁨: fix: 버그 수정                        (내용 없음)
```

---

## 2. 본문 템플릿

아래 3개 섹션 구조를 고정으로 사용한다. 섹션을 임의로 추가하거나 삭제하지 않는다.

```markdown
## 작업 배경 (Why)

---

## 작업 내용 및 고민 (What, How)

---

## 리뷰 포인트 (Review Points)
```

### 작업 배경 (Why)

- 이 변경이 왜 필요한지 기술한다.
- 근거는 연결된 이슈, 커밋 메시지, 코드 주석, diff에서 드러난 사실로 한정한다.
- 근거가 없으면 비워두고 `> 작성 필요: 작업 배경 확인 요망` 한 줄만 남긴다. 그럴듯한 배경을 지어내지 않는다.

### 작업 내용 및 고민 (What, How)

- 무엇을 어떻게 바꿨는지 항목별로 기술한다.
- 단순 파일 목록 나열이 아니라, 변경의 단위를 기준으로 묶는다.
- 선택 가능한 대안이 있었고 diff에서 그 흔적이 확인되는 경우(주석, 삭제된 코드, 설정값 변경 등)에만 "고민"을 언급한다.

### 리뷰 포인트 (Review Points)

- 리뷰어가 특히 확인해야 할 부분을 지목한다.
- 다음에 해당하는 변경이 있으면 반드시 포함한다.
  - 공개 API, 인터페이스, DB 스키마 변경
  - 트랜잭션, 동시성, 인증/인가 관련 로직
  - 외부 시스템 연동 또는 설정값 변경
  - 삭제되거나 주석 처리된 기존 로직
- 해당 사항이 없으면 `특이사항 없음`으로 표기한다.

---

## 3. 서식과 분량

- 수평선(`---`)은 위 템플릿에 명시된 섹션 구분 용도로만 사용한다.
- 코드 인용은 필요한 최소 범위만 포함한다. diff 전체를 복사하지 않는다.
- 목록의 각 항목은 한 줄로 끝내는 것을 원칙으로 한다.
- 변경 규모를 자랑하지 않는다. `총 15개 파일 수정` 같은 diff 통계를 재기술하지 않는다.
- `~하였습니다만`, `확인 부탁드립니다` 같은 인사말을 넣지 않는다.

| 변경 규모 | 본문 분량 |
| --- | --- |
| 단순 수정 (1~2 파일) | 섹션당 1~2줄 |
| 일반 기능 (3~10 파일) | 섹션당 2~5개 항목 |
| 대규모 변경 | 섹션당 최대 8개 항목, 초과 시 상위 개념으로 묶음 |

전체 본문은 리뷰어가 1분 내에 읽을 수 있는 길이를 넘지 않는다.

---

## 4. 출력 예시

제목과 본문은 별개로 제출한다. 아래 `제목:` 표기는 설명용이며 본문에 포함하지 않는다.

```markdown
제목: fix: 주문 취소 시 재고가 복구되지 않는 문제 수정

## 작업 배경 (Why)

- 주문 취소 API 호출 시 `OrderService.cancel()`이 주문 상태만 변경하고 재고 복구를 수행하지 않음

---

## 작업 내용 및 고민 (What, How)

- `OrderService.cancel()`에 `InventoryService.restore()` 호출 추가
- 주문 상태 변경과 재고 복구를 단일 트랜잭션으로 묶어 부분 실패 방지
- 이미 취소된 주문에 대한 중복 호출 시 `IllegalStateException` 발생하도록 가드 추가
- 재고 복구 실패 시 취소 자체를 롤백할지, 취소는 유지하고 보상 처리할지 선택지가 있었으나 전자로 처리함

---

## 리뷰 포인트 (Review Points)

- `@Transactional` 전파 범위가 기존 `OrderFacade`와 충돌하지 않는지 확인 필요
- 부분 취소(수량 일부) 케이스는 이번 변경 범위에 포함되지 않음
```
